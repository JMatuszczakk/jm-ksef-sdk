# AGENTS.md

Instructions for AI coding agents (Claude Code, Cursor, Copilot Workspace, etc.) working
in this repository. Human contributors: see [CONTRIBUTING.md](CONTRIBUTING.md) instead.

## What this repo is

`jm-ksef` is a small, zero-dependency TypeScript library that implements the client side
of the **KSeF** (Krajowy System e-Faktur — Poland's national e-invoicing system) API v2
protocol: authentication, encrypted online/batch invoice sessions, invoice metadata
querying, async export, and QR verification links.

It is a **library**, not an application. There is no server, no database, no UI. Callers
bring their own invoice XML and their own persistence for tokens if they need to survive
restarts.

## Hard constraints — do not violate these

- **Zero runtime dependencies.** `devDependencies` may only contain `typescript` (and
  test tooling if ever needed — prefer Node's built-in `node:test` over adding one).
  Do not add a fetch polyfill, a crypto library, a zip library, or a date library.
- **Platform-neutral.** Every line of `src/` must run unmodified on Node.js 20+,
  evergreen browsers, Cloudflare Workers, and Deno. That means: only `fetch`,
  `globalThis.crypto.subtle`/`crypto.getRandomValues`, `TextEncoder`/`TextDecoder`,
  `atob`/`btoa`, and standard ES2022. No `node:` built-ins (no `crypto` module, no
  `Buffer`, no `fs`) in `src/`. Test files under `test/` running via `node --test` are
  the one place Node-only APIs are fine.
- **No invoice-XML generation.** Building FA(2)/FA(3) invoice documents is explicitly
  out of scope — this library only moves already-built XML through the KSeF protocol.
- Don't reintroduce app-specific concerns that were deliberately stripped out when this
  library was extracted from a larger app: no D1/SQL persistence, no Hono/Express
  routing, no at-rest token encryption tied to a specific storage backend. Token
  persistence is the caller's responsibility (`KsefSession.tokens` /
  `restoreTokens()`).

## Repo layout

```
src/
  types.ts    KSeF API v2 types (request/response shapes)
  crypto.ts   WebCrypto helpers: RSA-OAEP, AES-256-CBC, SHA-256, base64
  http.ts     Thin fetch wrapper + KsefApiError
  zip.ts      Minimal STORE-only ZIP builder for batch session uploads
  client.ts   KsefSession (+ OnlineSession/BatchSession) — the public high-level API
  index.ts    Public exports — this is the package's entire surface area
test/         node:test suites, run against the *compiled* dist/ output
docs/         Protocol notes that don't belong in the README
```

`dist/` is generated by `tsc` and is gitignored — never edit it, never commit it.

## Before committing a change

```bash
npm run typecheck   # must pass with zero errors
npm run build       # regenerates dist/
npm test            # runs test/*.test.js against dist/
```

All three must succeed. `prepublishOnly` re-runs build + test, so a broken build blocks
publishing — don't rely on that as your only check locally.

## Conventions

- 4-space indentation, double quotes, explicit return types on every exported
  function/method (matches the existing `src/` files — follow them, don't reformat them).
- Keep `KsefSession` the one blessed high-level entry point. If you add a new KSeF
  endpoint, add a method to `KsefSession` in `client.ts` *and* make sure any new types
  it needs are in `types.ts` and re-exported from `index.ts`.
- Errors from the KSeF API must surface as `KsefApiError` (status/code/message/details),
  never a bare `Error` from inside `http.ts`'s response handling.
- When extending crypto helpers, add a unit test in `test/crypto.test.js` — these run
  fast and don't need network access, unlike anything hitting the live KSeF sandbox.
- Update `CHANGELOG.md` under `[Unreleased]` for any user-facing change (new method,
  changed signature, bug fix). See `CONTRIBUTING.md` for the release process.

## Things that look like bugs but aren't

- `KsefSession` methods throw `"Not connected — call connect() first"` before
  `connect()`/`restoreTokens()` has been called — this is intentional guard behavior,
  not a missing null check to "fix".
- `buildSimpleZip` uses STORE (no compression) deliberately — KSeF only requires a
  structurally valid ZIP, and adding DEFLATE would mean shipping a compression
  implementation for no protocol benefit.
